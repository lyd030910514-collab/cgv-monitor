# CGV 예매 오픈 감시 봇 v2 — 설치 튜토리얼

홍대 CGV '요루시카' 예매가 열리면 디스코드로 알려주는 봇입니다.
GitHub Actions에서 24시간 자동으로 돌아가고, 내 컴퓨터는 꺼도 됩니다.

## 이번 버전에서 달라진 점

| 기능 | 동작 |
|---|---|
| 날짜 화면 스크린샷 | 3분마다 날짜 줄 주변을 찍어 디스코드로 보냅니다. 기본은 **같은 메시지를 계속 수정**해서 채널이 도배되지 않아요. |
| 정상 작동 알림 | 연속 10번(약 30분) 성공할 때마다 "🔄 정상 작동 중"을 보냅니다. 중간에 한 번이라도 실패하면 0부터 다시 셉니다. |
| 자가 복구 | 실패하면 ① 열린 페이지로 재시도 → ② 브라우저를 새로 만들어 처음부터 → ③ 잠깐 쉬고 한 번 더. 그래도 안 되면 **그 순간의 화면과 실패 단계**를 보냅니다. |
| 접속 차단 | 차단된 화면도 찍어서 보내고, 새 서버로 재시작합니다. |
| 속도 | 브라우저를 계속 켜 두고 새로고침만 합니다. 예매 화면 주소를 저장해서 바로 이동하고, 고정 대기 대신 "화면에 뜨면 바로 진행"으로 바꿨어요. 이미지, 폰트, 추적 스크립트는 받지 않습니다. |

> 디스코드로 말하면 AI가 코드를 고치는 기능은 이번에 넣지 않았습니다.

---

## 1단계. 준비물

- GitHub 계정
- 디스코드 웹훅 URL (이미 쓰던 것 그대로 사용 가능)

## 2단계. 저장소 만들기

1. GitHub 접속 → 오른쪽 위 **+** → **New repository**
2. 이름 입력 (예: `cgv-monitor`)
3. 공개 범위를 고르세요. **중요**
   - **Public**: Actions 사용 시간이 무제한 무료입니다. 24시간 돌릴 거면 사실상 이쪽이에요.
   - **Private**: 월 무료 시간이 제한돼 있어서(보통 2,000분), 24시간 돌리면 며칠 안에 한도가 끝납니다.
4. **Create repository**

## 3단계. 파일 올리기

zip을 풀면 아래 구조가 나옵니다. **폴더 구조 그대로** 올려야 해요.

```
cgv-monitor/
├─ monitor.py
├─ requirements.txt
├─ README.md
└─ .github/
   └─ workflows/
      └─ monitor.yml
```

### 방법 A. 웹에서 올리기 (쉬움)

1. 저장소 화면에서 **uploading an existing file** 클릭
2. `monitor.py`, `requirements.txt`, `README.md`를 끌어다 놓고 **Commit changes**
3. `.github` 폴더는 숨김 폴더라 끌어다 놓기가 잘 안 될 수 있어요. 그럴 땐 이렇게 하세요.
   - **Add file → Create new file**
   - 파일 이름 칸에 `.github/workflows/monitor.yml` 을 입력합니다. `/`를 치면 폴더가 자동으로 만들어져요.
   - `monitor.yml` 내용을 통째로 붙여넣고 **Commit changes**

### 방법 B. 터미널(git)

```bash
git clone https://github.com/내아이디/cgv-monitor.git
cd cgv-monitor
# zip에서 푼 파일을 이 폴더에 복사 (.github 폴더 포함)
git add -A
git commit -m "CGV monitor v2"
git push
```

> 기존 저장소를 그대로 쓴다면 `monitor.py`, `monitor.yml`, `requirements.txt` 세 파일만 덮어쓰면 됩니다.

## 4단계. 웹훅 등록하기 (권장)

코드 안에 웹훅 주소가 기본값으로 들어 있어서 등록 없이도 동작은 합니다. 하지만 **저장소를 Public으로 쓰면 누구나 코드에서 웹훅 주소를 볼 수 있어요.** 그러면 누군가 내 디스코드 채널에 메시지를 보낼 수 있습니다.

1. 저장소 → **Settings → Secrets and variables → Actions**
2. **New repository secret**
3. Name: `DISCORD_WEBHOOK_URL` / Secret: 웹훅 주소 → **Add secret**
4. 코드에서 `monitor.py` 상단의 `or "https://discord.com/..."` 부분을 지우면 마무리입니다. 이미 주소가 공개됐다면 디스코드에서 웹훅을 삭제하고 새로 만들어 쓰세요.

## 5단계. Actions 켜기

1. 저장소 → **Actions** 탭
2. "I understand my workflows, go ahead and enable them" 같은 버튼이 보이면 클릭
3. 왼쪽에서 **CGV Monitor**가 보이는지 확인

## 6단계. 5분 테스트

1. **Actions → CGV Monitor → Run workflow**
2. `restart`는 `false`, `minutes`는 **5**로 두고 **Run workflow**
3. 1~2분 뒤 디스코드에 아래가 오면 성공입니다.
   - "✅ CGV 모니터링 시작"
   - "📅 [시각] 날짜 상태: ..." 메시지와 날짜 줄 이미지
4. 3분 뒤 같은 📅 메시지가 새 내용으로 **수정**되는지 확인하세요.
5. Actions 탭에서 실행을 눌러 로그를 보면 `status: 29✓ 30✗ ...` 같은 줄과 `이번 확인 소요 ○○초`가 찍힙니다.

### 테스트에서 이상할 때

| 증상 | 원인과 대처 |
|---|---|
| 아무 메시지도 안 옴 | 웹훅 주소 확인. Actions 로그에서 `discord error` 검색 |
| "⚠️ 확인에 실패했어요"와 화면이 옴 | 화면 이미지와 **단계**(예: 극장 선택)를 보세요. 그 단계에서 CGV 화면이 어떻게 보이는지가 단서예요. |
| 날짜가 전부 ✓ 또는 전부 ✗ | 활성/비활성 판단이 어긋난 것입니다. 스크린샷을 기준으로 알려주세요. |
| 스크린샷이 이상하게 잘림 | `SHOT_MODE`는 그대로 두고 알려주세요. 잘라내는 영역을 조정하면 됩니다. |
| 🚫 접속을 막았어요 | GitHub 서버 IP가 CGV에 차단된 것입니다. 자동으로 새 서버로 재시작하니 잠시 기다려 보세요. |

## 7단계. 본 실행

테스트가 잘 되면 **Run workflow → restart: false, minutes: 330**으로 한 번 실행하면 끝입니다.
이후에는 5시간 30분마다 스스로 다시 시작합니다. 20분마다 도는 cron은 끊겼을 때의 백업입니다.

## 멈추는 방법

실행을 취소(Cancel)만 하면 **20분 뒤 cron이 다시 켭니다.** 완전히 멈추려면 이렇게 하세요.

1. **Actions → CGV Monitor → 오른쪽 위 ⋯ → Disable workflow**
2. 돌고 있는 실행이 있으면 들어가서 **Cancel workflow**

다시 켤 때는 **Enable workflow**를 누르세요.

## 설정 바꾸기

`.github/workflows/monitor.yml`의 `env:` 부분을 고칩니다.

| 이름 | 뜻 | 기본값 |
|---|---|---|
| `CUTOFF_DATE` | 이 날짜 이후(당일 포함)가 열리면 "예매 오픈" 알림 | `2026-10-30` |
| `INTERVAL_SEC` | 확인 간격(초) | `180` |
| `HEARTBEAT_EVERY` | 연속 N번 성공마다 정상 알림 (0이면 끔) | `10` |
| `SHOT_MODE` | `edit` 한 메시지 수정 / `each` 매번 새 메시지 / `change` 날짜 상태가 바뀔 때만 / `off` 안 보냄 | `edit` |
| `MENTION` | 예매 오픈 알림에 붙일 멘션. 예: `@everyone` | 없음 |

영화나 극장을 바꾸려면 `monitor.py` 상단의 `KEYWORD`, `MOVIE_TITLE`, `THEATER` 기본값을 고치거나, 같은 이름의 환경변수를 `env:`에 추가하세요.

> 간격을 1분 이하로 줄이면 CGV 차단이 훨씬 잦아집니다. 3분 유지를 추천해요.

## 알아둘 점

- **이 코드는 실제 CGV 사이트에서 돌려 보지 못했습니다.** 제가 CGV에 접속할 수 없는 환경이라, 기존 코드의 동작 방식을 바탕으로 문법 검사와 날짜 계산 테스트까지만 했어요. 첫 5분 테스트에서 화면이 이상하면 디스코드에 온 스크린샷과 Actions 로그를 보여 주세요. 그걸 보고 바로 고칠 수 있습니다.
- 속도를 올리는 핵심은 "예매 화면 주소를 저장해서 바로 이동"하는 것인데, 이 주소가 실제로 영화를 가리키는지는 첫 실행에서 확인이 필요합니다. 안 맞으면 자동으로 느리지만 확실한 경로(검색부터)로 돌아가니 동작은 멈추지 않아요.
- 스크린샷에는 이미지와 폰트를 받지 않기 때문에 포스터 등이 비어 보일 수 있습니다. 날짜 확인에는 문제없어요.
- "코드를 스스로 고치는" 기능은 없습니다. 대신 대체 경로로 재시도하고, 안 될 때는 화면과 단계를 보내 줍니다.
